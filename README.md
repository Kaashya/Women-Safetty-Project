# Women Safety Analytics — CCTV Safety Monitoring Prototype

An AI-powered CCTV safety monitoring prototype designed to process surveillance video streams, detect and track people, identify potential safety events (predefined distress gestures and sustained proximity/close-following), and prepare structured event feeds for human verification.

> **IMPORTANT DISCLAIMER**  
> Alerts generated by this system represent **potential safety events requiring human verification** and **NOT confirmed crimes, harassment, or definitive emergencies**. All alerts are marked as `pending` and require a human operator to verify or dismiss them before any operational action is taken.

## 5. Member 2 Safety Analytics Details

### Event 1: Predefined Distress Gesture (`potential_distress_gesture`)
- **Definition**: Both hands/wrists intentionally raised above the shoulders/head region and held for a sustained period ($\ge 1.0\,\text{s}$).
- **Landmarks**: Left/Right Wrist and Left/Right Shoulder via MediaPipe Pose.
- **Rules**:
  - Wrist elevation: $y_{\text{wrist}} < y_{\text{shoulder}}$ for both wrists.
  - Landmark visibility: $\ge 0.5$ for all key landmarks.
  - Single raised hand is rejected.
  - Brief noisy raised hands are rejected via temporal frame counter ($\ge 10$ frames).
  - Maintained per `track_id` with a $5.0\,\text{s}$ cooldown to prevent duplicate alerts.

### Event 2: Sustained Proximity / Close-Following (`sustained_proximity`)
- **Definition**: Two tracked people remain unusually close while moving in correlated directions for a sustained period ($\ge 2.0\,\text{s}$).
- **Rules**:
  - Representative ground position: bottom-center of bounding box ($x = \frac{x_1 + x_2}{2}, y = y_2$).
  - Normalized distance: Euclidean distance scaled by average bounding-box height ($\le 1.3$).
  - Movement consistency: Cosine similarity of motion vectors ($\ge 0.40$).
  - Opposing path-crossings (e.g. walking past each other) are rejected.
  - Stationary standing bystanders (no active displacement) are rejected.
  - Maintained per canonical pair $(\min(id_a, id_b), \max(id_a, id_b))$ with an $8.0\,\text{s}$ cooldown.

## 6. Standard Safety Event Contract (Member 3 Handoff)

Member 3 only needs to consume:
```python
from src.detection.person_detector import PersonDetector
from src.safety import SafetyEventDetector

person_detector = PersonDetector(confidence=0.4, track=True)
safety_detector = SafetyEventDetector(camera_id="CAM_01")

for frame_data in person_detector.process_video(video_path):
    events = safety_detector.process_frame(frame_data)
    annotated_frame = safety_detector.annotate_events(
        frame=frame_data["annotated_frame"],
        events=events,
        people=frame_data["people"]
    )
```

Every emitted event conforms strictly to:
```json
{
  "event_type": "potential_distress_gesture",
  "track_ids": [2],
  "timestamp": 12.7,
  "frame_id": 381,
  "camera_id": "CAM_01",
  "confidence": 0.84,
  "status": "pending",
  "details": {
    "held_duration_sec": 1.4,
    "consecutive_frames": 14,
    "wrist_elevation": 0.22,
    "disclaimer": "Potential distress gesture requiring human verification."
  }
}
```

## 8. Privacy, Ethics & Responsible AI

1. **Generic Person Detection Only**:
   - The model is restricted to generic person detection (COCO class 0).
   - **No facial recognition**, gender classification, age estimation, or demographic profiling is implemented.
2. **Temporary Session-Level IDs**:
   - Tracking IDs (`Person 1`, `Person 2`) are short-lived video sequence counters. They do not represent real-world identities.
3. **Probabilistic Triage & Human Verification**:
   - System outputs are framed as **"Potential Safety Events"** or **"Potential Distress Gestures"**.
   - No automated accusations or claims of confirmed crimes; human operator verification is mandatory.
4. **Camera Distance Limitations**:
   - Monocular CCTV cameras cannot measure true 3D distances in meters; proximity is measured in normalized image-space scale.
